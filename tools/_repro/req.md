# 需求：卡片检索器的索引过程需要崩溃安全

对象：卡片检索器.py（SillyTavern 角色卡检索器，单文件，仅标准库 tkinter/sqlite3/zlib/base64）

## 现状
index_all 扫描 PNG 时按 batch=300 批量提交到 SQLite；增量判断只依赖 (文件大小, 修改时间)。

## 问题
1. 中途失败或用户点「停止」时，已提交的半批记录与未处理的卡混在一起，重启后无法判断哪些卡已完成、哪些没有。
2. 若某张卡的抽取过程本身出错（坏 PNG / 超大元数据），该卡会被反复扫描、反复失败，没有任何失败记录。
3. 库里没有「这次索引跑到哪」的状态，无法给用户可靠的续跑提示。

## 需要的最小侵入改动
1. 在库里引入索引运行状态（run 表或 meta 表字段）：记录本次 run_id、开始时间、结束时间、状态（running / finished / aborted）。
2. 每张卡的处理结果落库（成功 / 失败 + 失败原因 + 处理时间）；失败的卡在后续增量运行里可以重试，并且要能区分「文件内容变了」与「上次处理失败」。
3. 打开库或启动索引时做一次自检：若发现上次 run 处于 running 状态（说明异常退出），在状态栏给出提示，并允许用户选择继续或重做。
4. 不改动现有查询语法、不改动 GUI 布局与既有交互路径、不引入任何第三方库。

## 验收（可执行验证）
- 连续跑两次增量索引：第二次应跳过所有已完成的卡，不重复解析 PNG。
- 索引进行中强杀进程后重启：库中不残留「半完成」的卡（每张卡要么有完整记录、要么可被重做），再次运行能把未完成的补齐。
- 搜索功能回归正常：字段限定词（设定: / 世界书: / 开场白: / 标签: / 目录:）、AND 与排除语法、返回结果数量与改动前一致。
